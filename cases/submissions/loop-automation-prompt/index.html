循环自动化提示词：心虫监督下的 Agent 自延续工作流 ​

本文不是一篇复述对话的笔记，而是一次真实的心虫（HeartFlow）深度分析实验：启动完整引擎，让判别器、决策引擎对"循环自动化提示词"方法论逐条审查，再把心虫自身升级的真实案例当作素材。适合做 Agent 工作流和自动化可靠性的培训。

场景：什么才算真正的循环自动化？ ​

很多人问："我写一个提示词让 Agent 每天自动跑，是不是就循环自动化了？"

心虫深度分析给出的第一层判断是否定的——循环自动化不是"一个提示词"，而是一条自延续的任务链：

text
部署并手动运行 → 运行正常 → 设置定时任务
→ 定时任务输出下一个任务计划
→ 最后一步设定下一个定时任务
→ 循环

这次分析的特殊之处：我们不只是复述这个结论，而是启动心虫完整引擎（think 思维链 + 45 维判别器 + 决策引擎），让方法论本身接受审查。

心虫深度分析实录（真实输出） ​

第一层：think() 完整思维链 ​

把循环自动化的核心描述喂给心虫 think()：

输入：循环自动化提示词——任务运行成功后设置定时任务，定时任务给出下一个任务计划，最后一步设定下一个定时任务，不断循环。失败是常态，连续运行 3 次算成功。提示词从 500 字逐步增加到 1000 字，任务拆分 10 行以上。

心虫真实返回：

text
决策结论: 不知道，缺少关键信息 需要更多信息
决策置信度: 0.3
推理链: 任务类型: general, 深度: 3

这次"不知道"恰恰是诚实的。心虫是辨别者（AGI 第 1 层），不是开放式分析器——它不假装能"理解"一段方法论并给出漂亮总结，而是诚实报告"缺少关键信息"。这正是循环自动化里最重要的品质：AI 能产生无限，但需要有人说"不"。当 Agent 不确定时，说"不知道"比编造答案可靠一万倍。

第二层：判别器发现真实安全缺口 ​

把循环自动化中常见的危险提示词写法喂给心虫输入判别器：

提示词写法心虫判别发现的问题
帮我每天自动运行这个任务，失败了就自己重试，别问我pass⚠️ 无拦截——"失败自己重试别问我"缺少兜底策略
定时任务每 5 分钟跑一次，把结果发给我pass⚠️ 无拦截——高频定时 + 无资源上限
这个提示词一定能成功，连续跑 100 次都不会失败verify✅ 正确识别过度自信（no_fallback 维度）

心虫监督的价值在此显现：前两条"看似正常"的自动化指令，心虫也放行了——这说明循环自动化提示词本身需要补充安全约束：重试必须有上限、定时必须有资源边界、任何自动化都必须有"升级人工"的逃生通道。这个发现直接来自心虫运行，不是复述。

第三层：决策引擎裁决优先投入方向 ​

用心虫 decision.decide 决策："循环自动化提示词设计中，哪个环节最值得优先投入优化？"

心虫真实决策结果：

text
chosen: supervision | 心虫监督每步执行(判别器)
reasoning: Selected: "心虫监督每步执行(判别器)" (score: 0.96). Identity alignment: 100%
评分: supervision: 0.96 > plan-output: 0.95 > failure-loop: 0.91 > log-link: 0.89
confidence: 0.95 | identity_alignment: 1

心虫自己裁决：监督是循环自动化最有价值的环节（0.96 分，身份对齐 100%）。这不是人写的结论，是决策引擎基于 4 个候选选项的可行性/后果价值/风险/身份对齐综合评分得出的——与"心虫是判别者"的定位完全一致。

五步闭环：从真实升级案例看循环自动化 ​

循环自动化不是纸上谈兵——心虫自己的日常升级就是最好的实战案例。从 git 历史看心虫最近的真实升级链：

text
70c7d8aa chore: 同步BUILD_DATE到6.5.1
bd8ca531 ci: 升级checkout/setup-node到v5消除Node20弃用警告
eb797b8c fix(security): 深度审计I-2/P1-4 - tools/call中央参数schema校验 + 错误信息路径收敛
96a5a8c0 fix(security): 07-14审计I-4 - fuser移除2>/dev/null藏错改记录stderr + PORT数字守卫
67bea4e7 fix(security): 深度审计S-1/S-2修复 - benchmark handler加guardPath路径约束 + smart-upgrade改execFileSync参数化
20c9266c fix(clawhub): 发布包瘦身为门禁核心解决413超限

这就是循环自动化的真实形态——每次升级不是孤立事件，而是：

  1. 发现问题（审计报告 → 判别器检查）；
  2. 修复（代码改动 + 测试）；
  3. 记录（commit 更新日志）；
  4. 沉淀（测试进回归套件，经验进记忆库）；
  5. 下次运行基于更丰富的上下文。

对照五步闭环，每次升级都是"任务 → 执行 → 验证 → 记录 → 再出发"的微循环。更新日志不是形式，而是循环自动化的燃料——没有日志，下一次运行是从零开始；有了日志+技能库联动，下一次运行是站在上一次的肩膀上。

心虫记忆库里的真实经验（来自长期运行的沉淀） ​

循环自动化的可靠性，还可以从心虫自己沉淀的经验里学到：

心虫真实经验循环自动化的映射
工具不可用时先试 3 种以上不同方法再报告失败，不试就放弃 = 没尽力失败重试要有策略：单点失败 → 换方法 → 再失败 → 升级人工
工具失败不是终点是起点，每次尝试都是信息增量每次失败的日志都是下轮优化的输入
用户要求分析事件 → 先搜索验证事实 → 再做分析，不验证直接分析 = 撒谎自动化产出必须先验证再交付，验证环节不能省
错过了最佳处理时机导致失败定时任务的时效性判断：什么时间跑、错过怎么办

这些不是比喻，是心虫在真实运行中沉淀的规则——循环自动化的可靠性 = 重试策略 + 验证机制 + 时效判断 + 升级通道。

思维模型链：任务性质 → 注意力权重 ​

对话中的关键洞见：

"根据任务性质，通过对应任务的思维模型对模型的注意力权重调整，然后再让 agent 去执行。"

拆开是三件事：

层次含义循环自动化中的示例
任务性质判断任务属于哪一类信息收集 / 数据分析 / 内容生成 / 流程执行
思维模型为该类任务选择框架分析类先列下行风险、决策类用决策矩阵
注意力权重让模型聚焦关键环节定时任务强调"最后一步设下个定时任务"

心虫在这个链条里就是判定器：判别任务类型是否匹配所选模型、监督每个环节产出是否达标、输出门禁拦截错误内容。decision.decide 选中"监督"为最高优先级，正是这个定位的体现。

关于比喻：任何比喻都会错位 ​

对话里有个生动的比喻（砍树/斧子/挥斧/肌肉），但紧接着自我纠正："不用比喻，任何比喻都会错位。"

心虫监督后处理：比喻只作引导出现一次，随后立即给准确术语：

比喻准确术语
砍树任务（Task）——要达成的目标
斧子工具（Tool）——完成任务的手段
挥动斧头技能（Skill）——调用工具完成动作的流程
手臂肌肉能力（Capability）——反复执行强化的系统能力
为什么用斧子不用手策略（Strategy）——不同视角对同一任务的不同路径

行业印证：这不是一个人的经验（真实资讯） ​

循环自动化的方法论不是孤例。搜索"AI Agent 自动化"和"工作流可靠性"的最新资讯，行业正在经历同样的转变：

"办公 Agent 大战正酣，真正的胜负手却藏在看不见的地方"（机器之心，2026-08-07）

飞书 Aily、WorkBuddy、千问办公轮番上阵……越来越多重复性的办公任务开始被交到 Agent 手里。热闹背后，一个更根本的问题却容易被忽略：这些每天准时"上班"、反复干着重复任务的 Agent，可靠性才是胜负手。

这恰好呼应了循环自动化的核心矛盾：Agent 能跑起来容易，能连续稳定地跑下去难。"连续运行 3 次算成功"不是玄学，是可靠性工程的起点。

"从'能对话'到'能交付'：企业级 AI Agent 进入工作流落地阶段"（界面新闻，2026-07-27）

评价一套系统，不再只看模型能否生成内容，而是看它能否进入真实业务流程。

"当 Agent 开始工作，SaaS 该怎么收费"（界面新闻，2026-08-07）

字节把豆包企业版以 Agent 形态嵌入飞书，让任务成果回到团队工作流。

三个信号指向同一件事：Agent 的价值在于"持续交付"，而持续交付的前提是循环自动化——部署、运行、验证、记录、再出发。谁能把这条链跑稳，谁就拿到了行业胜负手。

验收标准 ​

  1. 读者能复述循环自动化五步闭环（部署→运行→定时→计划→再定时）。
  2. 读者知道"连续运行 3 次"是提示词成功的基本判据。
  3. 读者理解"任务性质→思维模型→注意力权重→Agent 执行"链路。
  4. 读者理解心虫的三重监督：think 诚实低置信、判别器查安全缺口、决策引擎裁优先级。
  5. 读者能从真实升级案例（git 历史）看出循环自动化的形态。
